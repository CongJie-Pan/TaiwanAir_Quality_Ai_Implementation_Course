# One-Hot Encoding (獨熱編碼) vs Target/Label Encoding

## 1. 為什麼要用 One-Hot Encoding？

在機器學習中，我們需要將文字類別（如「春」、「夏」）轉換成數字，機器才能運算。最直覺的方法是 **Label Encoding**，給每個類別一個數字：
*   春 = 0
*   夏 = 1
*   秋 = 2
*   冬 = 3

### ⚠️ Label Encoding 的問題
這種方式隱含了 **「順序」與「大小」** 的關係。
機器會誤以為：
1.  **大小關係**：3 (冬) > 0 (春)，難道冬天比春天「大」嗎？
2.  **運算關係**：1 (夏) + 2 (秋) = 3 (冬)，這在邏輯上完全不通。

這種錯誤的暗示會誤導模型（特別是線性回歸、神經網路），導致預測效果變差。

---

## 2. 什麼是 One-Hot Encoding？

**One-Hot Encoding** 的核心概念是將每一個類別變成一個**獨立的開關**。
如果有 4 個季節，就變成 4 個欄位，每個欄位只有 **0 (否)** 或 **1 (是)**。

### 數據範例
以「夏天」這筆資料為例：

| 欄位 (Features) | 數值 | 白話解讀 |
| :--- | :--- | :--- |
| `season_spring` | **0** |這 是春天嗎？ -> **否** |
| `season_summer` | **1** | 這 是夏天嗎？ -> **是** |
| `season_autumn` | **0** | 這 是秋天嗎？ -> **否** |
| `season_winter` | **0** | 這 是冬天嗎？ -> **否** |

因為同一個時間點只會是一個季節，所以這 4 個欄位中，**永遠只有一個是 1 (Hot)，其他都是 0**。這就是 "One-Hot" 名稱的由來。

---

## 3. 機器如何解讀？（數學視角）

這樣做的好處是讓模型可以為**每一個季節學習獨立的權重**，互不干擾。

假設模型的預測公式為：
$$AQI = \text{基礎值} + (W_1 \times \text{春}) + (W_2 \times \text{夏}) + (W_3 \times \text{秋}) + (W_4 \times \text{冬})$$

當輸入是夏天 (`0, 1, 0, 0`) 時，公式變成：
$$AQI = \text{基礎值} + (W_1 \times 0) + (W_2 \times 1) + (W_3 \times 0) + (W_4 \times 0)$$
$$AQI = \text{基礎值} + W_2$$

**結果：** 模型會直接學到 **$W_2$ 就是「夏天對 AQI 的具體影響」**（例如夏天 AQI 平均低 15，則 $W_2 = -15$）。

### 總結
*   **Label Encoding (0,1,2)**：適合有順序意義的資料（如：S, M, L, XL 或 低/中/高）。
*   **One-Hot Encoding (0,1,0)**：適合**沒有順序關係**的分類資料（如：季節、縣市、顏色）。雖然欄位變多了，但給出的訊號最乾淨、最明確。
